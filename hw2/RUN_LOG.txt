Determinism note: gensim Word2Vec with workers>1 uses multi-threaded async SGD, which is not
exactly reproducible under a fixed seed. We tested workers=1 (single-threaded) on the full
25k-review IMDB fine-tuning corpus, 5 epochs: measured 243.2s (~4 min) — well under the
practicality threshold — so workers=1 was used for the reported run, giving true determinism
under SEED=1605 rather than documented non-determinism.

reproducibility rule to document what was tried):
  1. gensim.downloader SSL certificate verification failure on this machine's Python.org build
     (macOS does not ship CA certs to python.org Python by default). Fix: set
     SSL_CERT_FILE to certifi's bundle before calling api.load("word2vec-google-news-300").
  2. gensim 4.4.0's KeyedVectors.intersect_word2vec_format() (used to seed the fine-tuning run
     from the pretrained GoogleNews vectors) calls np.fromstring() in binary mode, which NumPy
     2.x removed. Fix: a small compatibility shim routes binary np.fromstring calls to
     np.frombuffer before the intersect call; documented inline in the notebook.

Timing methodology: 1 untimed warmup + best-of-3 timed repeats for every timed comparison

showed a cold-start MPS kernel-compile artifact (see below).

Non-fatal issues hit during initial development (fixed before this final run):
  1. MPS cold-start artifact: the first activation-checkpointing timing comparison showed
     checkpointing as *faster* than no-checkpointing, the wrong direction. Root cause: MPS
     compiles kernels lazily on first use, so whichever variant ran first absorbed a one-time
     compile cost. Fix: added an untimed warmup pass before timed repeats, then took best-of-3 —
     produced the theoretically expected result (checkpointing ~25-28% slower, ~70% less
     activation memory) consistently afterward.
  2. torch.cuda.amp.GradScaler instantiates without raising off-CUDA hardware, but silently
     self-disables (is_enabled() == False, with a UserWarning) — confirmed live rather than
     assumed. Mixed-precision sections therefore use autocast without a scaler on MPS/CPU,
     documented in the notebook as GradScaler being CUDA-only.
  3. Under an earlier run (different seed), MPS matmul appeared to beat CPU matmul by ~1.2-2x
     for a 4096x4096 matmul; under this run's SEED=1605 + best-of-3 methodology the two are near
     parity (0.98x, i.e. CPU marginally faster). The notebook's Section 1 findings, the summary
     table, and the overall discussion were corrected to state the new, honest result rather
     than leave the earlier claim standing — see METRICS.md.
